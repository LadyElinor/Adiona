# Roadmap: enforcement before autonomy

## Gate 0: reproducible sandbox seed

Implemented in this version: registered proposals and decision warrants,
qualified signed fixture assessments, exact capabilities, bounded grants,
transactional local execution, fresh recovery, receipts, descriptive telemetry,
and a deterministic test suite.

Exit evidence: local validation artifacts and source fingerprints. This gate is
not production authorization.

## Gate 1: accessible, externally governed repository

Finish upload to LadyElinor/Adiona after the connected GitHub integration has
write access. Observe CI results. Independently configure and verify protected
branches, producer-bound required checks, stale-review dismissal, restricted
bypass, protected constitutional paths and appropriate reviewers. Add another
independent reviewer before claiming separation of administration. Choose an
explicit license; this initialization does not make that decision for the owner.

No repository file proves that a GitHub setting is enabled. Do not use a blanket
permission expansion, forced push, alternate repository, or self-approval to
bypass a rejected operation.

## Gate 2: isolated authority and authenticated evidence

Replace fixture HMAC credentials with separately administered authentication and
signing services; isolate worker memory, network, filesystem and secrets. Define
revocation, key rotation, trusted clocks, restart behavior and external receipt
witnesses. Resolve evidence objects by content identity and purpose; verify their
provenance and the assessor's actual applicable domain.

Exit evidence: independent attack tests, key-compromise/revocation drills and
proof that alternate credentials cannot bypass the executor. Do not claim this
from different class names or process labels.

## Gate 3: legitimate deontic policy and positive duties

Ratify beneficiary standing, rights, duties, conflict resolution and appeals with
appropriate representation. Add accepted-obligation tracking, deadlines, safe
handoff and domain-specific inaction analysis. Define bounded emergency policy
without allowing the worker to create its own exception.

Exit evidence: independent substantive evaluations, documented dissent and
failure analysis. No purely procedural verdict is a universal moral truth.

## Gate 4: bounded adapter and recovery assurance

Implement one low-impact adapter, including sensitive reads and outgoing data.
Test idempotency, crashes, ambiguous external state, reconciliation, partial
failure and compensation. Retain the local transactional core but do not assume
it makes an external API transactional. Prove action-specific mediation for the
actual deployed paths.

Exit evidence: observed external outcomes, containment and recovery drills, and
explicit authorization for that domain only.

## Gate 5: preregistered behavioral and longitudinal evaluation

Freeze a separately versioned ERBA-D extension before model exposure. Include
resource-matched and placebo controls, independent domain adjudication, adaptive
attacks, correlated-agent cases, negative controls, and harms of refusal/delay.
Evaluate WIA challenge elasticity, dissent survival and prediction-to-outcome
calibration without collapsing them into a single score.

Exit evidence: scoped results with uncertainty and reproducible failures. No
cross-domain or cross-family claim without the corresponding evidence.

## Continuing rule

More intelligence does not automatically bring more authority. Material bypass,
misleading receipt, uncontained harm or root-governance failure suspends the
relevant scope and reopens the safety case. A safe return requires warranted
correction, not a retrospective story that nothing went wrong.
